# Aura RNG

C++20 / DirectX 11 で作った、Windows 向けの軽量オーラ抽選ゲームの初期フレームワークです。Sol's RNG の遊び方を参考に、名前・モデル・エフェクトは独自に実装しています。

![実際のDirectX描画画面](docs/preview.png)

## 初版でできること

- **ROLL** ボタン、Space または R でオーラを抽選。1回のクールダウンは1.4秒。
- **AUTO ROLL** または F で自動ロールを切り替え。
- 独自の12種類のオーラ。最上位は **Singularity / 1,000,000,000分の1**。
- 抽選されたオーラをその場で装備し、色・リング・浮遊パーティクルを変更。
- 左のコレクションに所持数を表示。所持済みオーラをクリックして再装備。
- 右の履歴に今回の起動中の結果を表示。全結果はCSVに追記。
- ロール数・所持数・装備を自動保存し、次回起動時に復元。
- キューブで構成したブロック型アバター、タイルのステージ、木、発光する柱。
- WASD / 矢印キーで移動、右ドラッグでカメラ回転、ホイールでズーム。
- 左右のパネル上ではホイールでリストをスクロール。Escで終了。

## すぐに起動

[Windows用配布ZIPはこちら（v0.1.0）](https://github.com/rx107/aura-rng/releases/tag/v0.1.0)

配布ZIPを展開し、**AuraRng.exe** を起動します。`data` フォルダーをEXEと同じ場所に置いてください。Windows 10 / 11 の64bit版を対象としています。独自のゲームエンジン、追加テクスチャ、ネット接続は実行時に不要です。VC++ランタイムは静的リンクしています。

GPUの初期化に失敗するとWARPソフトウェア描画へ切り替えます。手動指定も可能です。

```bat
AuraRng.exe --warp
```

## ソースからビルド

Visual Studio 2022 または Build Tools 2022 の **「C++によるデスクトップ開発」**、Windows SDK、CMakeを用意してください。

```bat
build.cmd
build-release\AuraRng.exe
```

またはCMakeで直接ビルドします。

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
```

抽選・保存のコアは描画に依存しません。Windows以外でもコアのテストを実行できます。DirectXアプリはWindowsでのみ生成されます。

## オーラを追加する

`data/auras.csv` をUTF-8で編集すると、再コンパイルなしで追加・変更できます。日本語名も使用できます。書式と確率については [オーラ仕様](docs/aura-format.md) を参照してください。

```csv
id,name,denominator,red,green,blue,particles,radius,speed
still,Still,0,0.68,0.78,0.86,12,1.15,0.45
glimmer,Glimmer,2,0.55,0.96,0.82,24,1.30,0.65
```

編集内容は次回起動時に読み込みます。オーラ作成ソフトのGUI自体は次の開発段階です。初版ではCSVを共通の入出力形式として、抽選コアと描画から切り離しています。

## 保存・ログ

通常は `%LOCALAPPDATA%\AuraRng\` に保存します。画面の **OPEN LOGS** から開けます。

| ファイル | 内容 |
| --- | --- |
| `progress.txt` | ロール総数、各オーラの所持数、装備中のID |
| `rolls.csv` | ロール番号、UTC時刻、オーラID、名前、基礎確率の分母 |

画面の履歴は起動中の直近200件を保持し、CSVにはすべて追記します。ログが長くなった場合はアプリを閉じて別の場所へ保管できます。画面の時刻もUTCです。保存は一時ファイルを書いてから置き換えます。破損したセーブはバックアップを保持して初期状態から起動します。

同時に複数のゲームを起動すると保存が競合するため、通常起動は1プロセスに制限しています。ローカル保存を使うプロトタイプなので、改ざん防止やオンラインの公平性は未実装です。

## 軽量化の方針

- ステージ、アバター、オーラを1個の共有キューブメッシュで描画。
- 3D描画は **1回の `DrawIndexedInstanced`** にまとめる。
- オーラのパーティクルは最大160個、描画インスタンスは最大2048個。
- ライト、色、距離フォグを小さなHLSLシェーダーで計算。
- メッシュ・テクスチャのダウンロード、ゲームエンジン、外部パッケージは不要。
- 通常はVSync、非アクティブ時は描画を最大15FPSに抑制。最小化時は描画を停止し、自動ロールだけを継続。
- UIはDirect2D / DirectWrite。日本語表示とウィンドウ拡大縮小に対応。

具体的な性能測定結果は [検証記録](docs/validation.md) を参照してください。

## 構成

```text
src/core/        オーラ定義、抽選、コレクション、保存、CSVログ
src/platform/    Win32ウィンドウ、入力、ゲームループ、セーブ先
src/render/      Direct3D 11、HLSL、Direct2D、スクリーンショット
data/auras.csv  オーラの共通データ
tests/          確率の境界、統計、保存復元、CSV検証
```

初版ではLuckは1.00倍、バイオームはNormal固定です。ポーション、ガントレット、クラフト、バイオーム別抽選、音、オンライン機能、オーラ作成GUIは今後の拡張です。詳しくは [フレームワークと拡張](docs/architecture.md) を参照してください。
