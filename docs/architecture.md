# フレームワークと拡張

## 現在の流れ

Win32入力 → `App` がクールダウンを確認 → `Roller` がチケット抽選 → `Progress` が所持数を更新 → CSVログ追記とセーブ更新 → `Frame` を `Renderer` に渡して描画します。

`aura_core` はWin32画面やDirectXデバイスを参照しません。CSVの読み込み、確率、進行データ、ログを単独でテストできます。Windows上でのセーブ置き換えだけはOS APIを利用します。

`Renderer` は読み取り用の `Frame` を受け取り、コレクションを書き換えません。UIのクリックは `Hit` を返し、変更は `App` が処理します。ゲーム状態を保持したまま描画デバイスを作り直せます。

`Progress::record()`は所持数と統計だけを更新します。`equipped`はコレクション操作から変更します。`Presentation`は装備と一時プレビューを分離し、プレビュー選択では自動ロールを停止するだけで抽選・ログ処理を呼びません。

`Definition::previewOnly`は確率未設定の試作を同じカタログへ載せるための指定です。CSVの任意の末尾列`preview_only`から読み込み、抽選のチケット配分とLuckのCDFから除外します。`Progress::record()`と`appendLog()`でも登録を拒否し、試作の追加で既存の確率や履歴を変えないようにしています。付属カタログは抽選13種類とPixelation・Equinox・BreakThroughの試作3種類、合計16種類です。試作はImGuiから表示し、未所持でもコレクション・履歴を変更しません。`pixelationPose()`・`equinoxPose()`をブロックとVRMで共有し、BreakThroughにも浮遊姿勢を適用して、移動中も固定します。

進行データのロード時には試作オーラの非0所持数を拒否し、初期装備とbestは抽選対象から選びます。保存時も試作の装備・best・非0所持数を拒否します。コレクションの達成数は抽選対象だけを数え、試作の追加で全取得が不可能にならないようにしています。

進行セーブschema 2は、編集可能な総ロール回数`rolls`と、引退したIDの所持数も含む実在庫合計`collected`を分離します。読み込み時は`collected`と各所持数の合計を検証し、回数変更後も在庫の整合性を確認します。旧schema 1は従来の総回数と在庫合計の一致を検証して読み込み、次回保存からschema 2へ移行します。プロフィールでは0〜10^15の総回数を指定でき、`App`がAutoRollを停止して`setRollCount()`を適用します。在庫・best・画面履歴・既存CSVを変更せず、その後のロールは新しい回数へ1加算します。回数を戻すと今後のCSV番号が過去と重なる場合があります。

ImGuiパネルは`DebugActions`を返し、ゲームループ側で適用します。`Settings` schema 4にLuck・バイオーム・アバター・音量・UTF-8のファイルパス、Pixelation用の2つのBGMパス、ゲーム内ユーザー名、Discord表示の有効・無効とApplication IDを保存し、schema 1〜3を引き継ぎます。ユーザー名は既定`Player`、1〜64 UTF-8バイトで改行・制御文字と不正なUTF-8を拒否します。Discordのアカウント名とは連動せず、任意のゲーム内表示名です。

Win32入力はImGuiのキャプチャを確認してからゲームへ渡します。ステージ上から始めた右ドラッグはカメラが所有し、ImGui上へ移動しても継続し、ボタン解放・フォーカス喪失・キャプチャ喪失で終了します。前フレームの`WantCaptureMouse`によるドラッグ中断を避けます。

`Roller::setLuck()`は基礎確率のCDFをL乗し、L回の最良結果と同じ分布を1回の抽選で扱います。高倍率でも合計100%を保ちます。バイオームは現在NormalとDesertの描画状態です。

`VrmAvatar`はcgltfとnlohmann/jsonで自己完結したVRM GLBを読み込み、初期モーフをCPUで適用し、スキン・階層・バインド行列を保持します。WICで画像を最大2048pxへ変換し、GPUに頂点・インデックス・テクスチャを作成します。読み込みは`std::async`の別スレッドで、即時コンテキストはメインスレッド専用です。読み込み後に巨大な元ファイルと未使用モーフを解放します。

描画時はGPUスキニングで最大512ボーンを扱います。VRMのhumanoid割り当てから腕・脚・膝を認識し、衣服が持つ同名の複製骨にもポーズを適用します。回転はレスト姿勢のモデル座標から親座標へ変換し、VRM 0.x / 1.0の前方軸と左右の違いを処理します。`avatarPose()`をブロックとVRMで共有し、通常は立ち姿と歩行、固定オーラでは歩行の位相・移動量に依存しない姿勢を返します。Spring Bone・表情アニメーション・MToonは今後の拡張です。

Singularityのレベルは安定IDに紐づく所持数から算出し、初取得0・重複ごとに+1・上限3です。保存値を追加せず、過去の所持数も反映します。プレビューのレベルは`Presentation`の一時値で、装備復元で解除します。星は丸い輪郭を持つ薄い3Dメッシュをインスタンス描画し、レベル3では`singularityStar()`の螺旋軌道を使います。ブラックホールは深度テスト付きのシェーダーで円盤・光輪・暗い中心を描画します。レベルは確率を変えません。

Pixelationは`render/pixelation.cpp`の専用インスタンス描画です。3つの回転するワイヤーキューブ、床リング、Player 1 / 2のHUD、5×7のビットマップ文字、180個のピクセル片と20個の光点を、線や四角形の共有メッシュから1バッチにまとめます。色は基準の演出時間で2秒周期とし、シアン・ライム・オレンジ・マゼンタを補間します。周囲のキューブ・粒子・色・HUD公転には`motion`時計を使い、レベル0は等速、レベル1〜2は1.6倍速、レベル3は3倍速で進めます。弾・爆発・アバターの浮遊には別の`action`時計を使い、レベル1〜3で1.6倍速を維持します。通常プレイでは両時計に`dt`を積分し、レベル変更時も位相を保ちます。スモークテストでは`pixelationMotionTime()`と`pixelationActionTime()`で任意時刻を再現します。

レベル2以降の打ち合いは`pixelationVolley(actionTime, orbitTime, shotOrbitTime)`から、現在のPlayer座標・発射時の座標・両球の座標・共通衝突点・発射と衝突のcycle IDを取得します。1.6 action秒ごと、実時間では両レベルとも1秒ごとに同時発射し、0.64 action秒（実時間0.4秒）で両球が同じ座標`(0, 3.60, 0)`へ到達します。`App`は発射cycleが変わった時だけ、その時点の高速公転から発射時のorbit時計`shotOrbitTime`を計算・保持します。飛行中にレベル2と3を切り替えても発射位置は動かず、Player自身はそれぞれの速度で公転を続けます。球は共通の進行率で補間し、到達時は両方へ同じ衝突点を明示的に代入します。音もaction時計の同じcycle IDから1回ずつ再生し、プレビュー・レベル変更時は判定の基準をリセットします。

衝突の最初のフレームから白い閃光、広がる衝撃波、放射状の破片を生成します。明るさは衝突直後を最大にして減衰させ、爆発が遅れて立ち上がらないようにしています。レベル2と3の爆発はともに0.65 action秒（実時間約0.406秒）で広がって消え、レベル3は規模だけを1.3倍にします。爆発の色は周囲と同じmotion時計から選びます。発射・衝突音は低い衝撃音と高い成分を重ねた短い合成音です。

PixelationとEquinoxは`R11G11B10_FLOAT`の全解像度発光ターゲットへ描画し、半解像度の2枚のターゲットで横・縦のブルームぼかしを行い、元の発光とともに画面へ合成します。Pixelationのブロック3D部分はワールド1回、演出1回、ぼかし2回、合成1回の計5 draw callsです。テクスチャは初回表示時に遅延確保してキャッシュし、1440×900で約7.4MiBです。リサイズ後は必要な大きさへ再作成します。標準オーラではこの後処理をスキップし、最大160粒子と既存描画経路を使います。Pixelationの180ピクセルと20光点は専用生成のため、CSVの標準粒子上限とは独立しています。

Equinoxは`render/equinox.cpp`で白黒の天体、星、床の回転する帯と銀色の粒子を生成します。天体内部は3Dノイズの密度場を動かし、球体の奥行き方向に5層を積み重ねて吸収と照明を計算し、表面模様ではなく厚みのある雷雲を表現します。短い二連の稲光で雲を背後から照らします。公転の半周、約0.7825秒ごとに2球の白黒を同時に交換し、常に一方が白で他方が黒になるよう同じ位相から材質を選びます。各球の中心光から約0.30秒分の過去の公転をたどる波状の光跡と小さな星を生成し、それぞれ独立して減衰させます。

`衡`は床の高さ0.240に寝かせた3.2×3.2単位の面へ描画し、文字全体が最も内側の半径2.1の円に余白を残して収まるようにします。周辺の霧は22個の薄い光片とし、6.25秒で半径4.25から0.15へ螺旋状に集まります。天体は専用のマテリアルをまとめて描画し、周囲の光はブルーム用バッチにまとめます。`EQUINOX`と副題は天体の白黒交換と同期させ、ブルーム合成後のアルファ描画で黒文字が発光に消されるのを防ぎます。これらと`衡`の文字はWindowsフォントから実行時に小さなテクスチャへ描き、フォントファイルは配布しません。

Equinoxの独立したカットシーンは`EquinoxCutsceneDuration`の10.9秒で管理します。`render/cutscene.cpp`の全画面三角形とプロシージャルシェーダーが回転する白黒の雲・星・リングを描き、Direct2Dが陰・陽・衡・無の4段階の字幕を重ねます。

BreakThroughは中央の高い塔、周囲の傾斜した塔、白青の渦と光、破片を共有の線・四角形から生成します。各柱は異なる位相と3.6〜4.65秒の周期で上下に浮遊し、ガラス・芯・付属する破片・頂部の光へ同じ移動を適用します。名前のプレートはアバター頭上の高さ3.55へ配置します。専用マテリアルと既存のHDRブルームを使い、参考GIFの画像をテクスチャとして貼り付けずに描画します。独立したカットシーンは30秒で、参考動画の構成をプロシージャル描画で再現し、内部の柱も個別に上下へ動かします。F1のオーラタブから通常プレビューとカットシーンのみの再生を選択できます。

カットシーンは`CutsceneKind`で種類を分け、開始時にAutoRollと入力を止め、通常のワールドとUI描画を置き換えます。終了・Esc・デバッグ停止で元の表示とレベル、デバッグ画面を復元します。所持数や装備を変更する処理は呼ばず、どちらも未所持で確認できます。

ステージは64×64単位、移動範囲は各軸±30.8へ拡張しました。床は大きなタイルを共有メッシュで描き、頂点数やdraw callを増やしすぎない構成です。頭上ラベルは3D位置を画面に投影してDirect2Dで描画します。

`Music`はMedia Foundationで音声をPCMへデコードし、XAudio2でループします。`Presentation::shown()`のIDとレベルからSingularity用、Pixelation Level 1〜2用、Level 3用の曲を選びます。通常の抽選結果では変わりません。曲の場所は設定で指定したファイル、EXEの`data/audio`、Downloadsの順で解決します。Tides of the Outer ReachはソースとZIP、新2曲は許可を得た公開ZIPへ同梱します。ソースからのビルドではZIPから音源をコピーするかローカルファイルを指定できます。

発射・衝突音は`SoundEffects`で初回に短いオリジナルPCMを合成し、固定数のXAudio2 voiceで再生します。毎フレームの再合成や音声のキューの蓄積を避け、連続フレームで同じイベントを重ねません。

カットシーンの音声はDownloads内のローカル動画に音声ストリームがある場合だけ別の`Music`で読み込みます。Equinoxは`EquinoxReworkedCutscene.mp4.mp4`の先頭から10.9秒、BreakThroughは`BreakthroughCutsceneV2.mp4.mp4`の4.5秒の位置から30秒分を使い、再生のたびに開始位置へ戻し、カットシーン終了時に即停止します。元動画はソース・配布ZIPへ含めず、見つからない場合は映像演出だけを再生します。参考GIFとVRMモデルも同梱しません。

星はベジェ曲線で角を丸めた共有Direct2Dパスです。クールタイムは進行率を左右の位置に対応させ、星と進行済みの線が正弦波の軌跡をたどります。開始・終端で透明度を変え、残り時間0では描画しません。

`App` が起動／終了、入力、手動・自動ロール、保存を管理します。例外をWin32ウィンドウプロシージャーから外に投げないよう、I/Oと描画の更新はゲームループ側で実行します。

## Discord Rich Presence

`platform/discord.cpp`の`DiscordPresence`は、Windowsデスクトップ版Discordのローカル名前付きパイプへIPCで接続します。公開Application ID `1560569853184573590`（Star's RNG）と表示有効を初期設定に持ち、トークンやSDK DLLは要求しません。ゲームループはユーザー名と総回数の小さなスナップショットを渡すだけで、接続・送受信・待機は専用ワーカーが担当します。

RPCのハンドシェイク後に`SET_ACTIVITY`で`details: Username: 名前`、`state: Rolls: 回数`を設定し、変更の送信間隔を5秒以上に制限します。名前付きパイプを再探索して切断から自動で再接続し、無効化・アプリ終了時は現在のアクティビティを消去する要求を送ります。F1のプロフィールタブに接続・待機・エラー状態を返します。Discord側のActivity Privacy設定によって他の利用者に公開されるかが変わり、IPC応答の成功だけではプロフィール上の表示確認を意味しません。

プロトコルは[Discord公式RPC資料](https://docs.discord.com/developers/topics/rpc)を参照しています。実Discord上の表示は未検証です。利用手順と状態の説明は[Discord連携](discord.md)を参照してください。

## 次に追加できるもの

1. **オーラ作成GUI**: `aura_core` を再利用した別EXE。定義編集、色選択、ライブプレビュー、CSVの検証付き出力。保存前の入力検証をコアと共通化。
2. **演出の種類**: 現在のリング／粒子に加えて、`effect_type` と `schema_version` を導入。独自メッシュや複数エミッターを導入する際は描画予算を設ける。
3. **バイオーム**: 既存の景観状態に時間・天候と適用条件を追加。通常確率とブレイクスルー確率を別々のデータとして扱う。
4. **装備 / ポーション**: 現在のLuck補正に一時効果と有効期限を追加。
5. **クラフト**: `Progress` の所持数を消費するレシピ、重複オーラの使い道、確認画面。
6. **オンライン化**: サーバー側抽選、アカウント、同期。クライアントのローカル乱数／セーブを信用する設計のままランキングを導入しない。

現在はシングルプレイヤーの試作です。物理エンジン・衝突判定は含めず、アバターはステージ内に制限しています。木・サボテン・柱は背景物です。ゲーム内課金はありません。
