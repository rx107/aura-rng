# オーラの共通データ仕様 v2

`data/auras.csv` はUTF-8、先頭行は固定です。v2では末尾に`preview_only`列を追加します。従来の9列ヘッダーもそのまま読み込め、その場合は全行を通常の抽選オーラとして扱います。BOM、CRLF、引用符付きフィールド、日本語名に対応しています。名前にカンマを含める場合は引用符で囲み、名前内の `"` は `""` と書きます。

| 列 | 意味 / 制限 |
| --- | --- |
| id | 保存用の安定したID。1〜64文字、小文字英字・数字・`_`・`-`。重複不可 |
| name | 表示名。1〜128 UTF-8バイト。改行・タブ不可 |
| denominator | 基礎確率 `1 / N` のN。2〜10^12。0は残余確率を受け取るオーラ（現在はStardust）。試作専用行も0を指定 |
| red / green / blue | 色。各0〜1 |
| particles | 浮遊パーティクル数。0〜160 |
| radius | リングと粒子の半径。0.5〜3 |
| speed | 回転速度係数。0〜4 |
| preview_only | v2の追加列。0は抽選対象、1は表示試作専用。1の場合はdenominator=0が必須 |

カタログは1〜4096件に対応します。試作専用行を除き、分母0の通常オーラがちょうど1件必要です。それ以外の抽選オーラの確率合計は1未満にしてください。範囲外・重複・不正な行は起動時にエラーにします。

`preview_only=1`は、確率を決める前の見た目の確認に使用します。チケットは常に0枚で、Luckによって当選することもありません。ImGuiから一時表示できますが、通常ロール・所持数・履歴へ登録せず、確率欄は`Preview only`を表示します。付属カタログは通常の抽選13種類と、Pixelation・Equinox・BreakThroughの試作3種類、計16種類です。コレクションの達成数も抽選対象だけを数えます。抽選を後から有効にする場合は`preview_only=0`と有効な分母を設定し、残余確率を確認してください。

## 抽選の意味

1回のロールにつき、`std::mt19937_64` と `std::uniform_int_distribution<uint64_t>` で0〜999,999,999,999の一様なチケットを1枚選びます。

各オーラのチケット数は `floor(10^12 / N)` です。通常オーラは残りを受け取ります。全オーラでチケットを分割するため、複数のオーラが同時当選することはありません。カタログの並び順によって希少オーラが通常オーラに上書きされることもありません。

付属データの正の分母はすべて10^12の約数なので、表示の`1 / N`と実確率が一致します。Commonは5,000億枚で正確に50%、Uncommonは2,500億枚で正確に25%、Singularityは1000枚で正確に10億分の1です。Stardustは残りの69,888,989,000枚（6.9888989%）を受け取り、`~1 / 14.31`と表示します。全13種類の実確率は異なります。頭上表示は同じ基礎値を`1 in 4`などの形式で示します。

任意の分母を追加した場合の切り捨て誤差は絶対確率10^-12未満です。0はCommonという名前を意味せず、残余確率の指定です。最もレアな発見も、残余を含む実際のチケット数から判定します。

このチケット配分はLuck 1倍の基礎確率です。Luck L倍では、基礎チケット数の大きい順（通常→希少）に並べた累積確率Fを`F^L`に変換し、隣との差を新しい配分にします。整数への丸め後も合計10^12枚を維持します。例えばCommonは2倍で25%です。小数の倍率も扱え、100万倍まで設定できます。画面のコレクションとCSVは基礎値を示し、ImGuiのワールドタブはLuck適用後の確率を表示します。回数による天井・保証、バイオーム補正はまだありません。

## IDと将来の作成ソフト

作成ソフトは、このCSVの各行をフォームから編集し、同じ検証条件で出力できます。表示名、色、粒子数、半径、速度を編集してプレビューするGUIを後から独立したターゲットとして追加する想定です。

保存は表示名ではなくIDを使います。並べ替えや名前変更で所持数は失われません。削除したIDの所持数もセーブ内に保持され、同じIDを再追加すると復元できます。新しいオーラは所持数0で追加されます。既存のIDを別のオーラに使い回さないでください。

旧版との互換性のため、CommonのIDは`still`、UncommonのIDは`glimmer`のままです。日本語画面では付属オーラのIDに対応する訳名を表示し、独自オーラの名前はそのまま表示します。

## Aura Levelと試作演出

IDが`singularity`または`pixelation`の場合、所持数から`min(3, max(0, count - 1))`でレベルを算出します。初取得は0、重複ごとに1上がり、最大3です。独立した保存値を持たないため、Singularityは旧セーブの所持数もそのまま反映します。デバッグのレベルは`Presentation::singularityLevel`と`pixelationLevel`に分かれた一時オーバーライドです。別のオーラのレベルを変更せず、レベル値は保存しません。

Singularityは0が従来の粒子、1が丸い星、2が小ブラックホール、3が大ブラックホールと星の吸収です。Pixelationは0が従来、1が演出速度1.6倍とRedline Shift、2が同じ速度で球の打ち合いです。3ではキューブ・粒子・色・HUD公転を3倍速へ上げ、弾・衝突から爆発・アバターの浮遊はレベル2と同じ1.6倍速に保ち、BGMをCensoredへ切り替えます。レベル2〜3は命中した最初のフレームから閃光・衝撃波・破片と合成効果音を発生させ、レベル3は爆発の規模を1.3倍にします。発射時の公転位置を保持するため、飛行途中にレベルを変えても弾の発射位置は跳びません。Pixelationは今回もプレビュー専用なので実取得はなく、所持レベルは0です。F1から演出の全レベルを確認できます。レベルで抽選確率や所持数が変わることはありません。

EquinoxとBreakThroughにはAura Levelを設定していません。Equinoxは多層の動く雷雲と二連の稲光を内部に持つ白黒の天体を1個ずつ表示し、約0.78秒ごとに白黒を交換します。各球の中心光から個別に流れる波状の光跡と星、最内周の円に収まる床の`衡`、少量の霧が中心へ集まる演出と、約10.9秒の独立したカットシーンを持ちます。主タイトルと副題も天体に同期して白黒を交換します。BreakThroughは中央の高塔・周囲の傾斜した塔・白青の渦と粒子、頭上の名前、約30秒の独立したカットシーンを持ち、通常表示とカットシーンの両方で柱が個別に上下へ浮遊します。

**F1 → オーラ**から、未所持の通常プレビューと各カットシーンのみの再生を選べます。カットシーン中はAutoRollと通常入力を止め、Escまたはデバッグ停止で元の表示とレベルへ戻します。所持数・装備・履歴は変更しません。カットシーン映像はコードで描画し、音声はDownloadsのローカル動画がある場合に使用します。BreakThroughは`BreakthroughCutsceneV2.mp4.mp4`の4.5秒の位置から30秒分を再生します。元動画・参考画像・VRMは配布物へ含めません。

これらの専用演出と音楽の切り替えはIDに紐づくC++コードで実装しており、CSVの`particles`などの標準パラメーターだけで全てを編集する形式にはなっていません。
